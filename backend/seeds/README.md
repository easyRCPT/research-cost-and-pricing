# Seeds

Data that lives in git, so every dev gets it automatically instead of loading it
by hand. Add a lookup table here once and nobody has to rebuild it again.

Use it for constants the app needs to work — funding bodies, salary scales,
indexation rates. Not test data; that goes in an app's `fixtures/`.

## Writing one

Number the files. They run in that order, which is how you seed a table after
whatever its foreign keys point at:

```
0010_funding_bodies.sql
0020_salary_scales.py
```

`.sql` runs as-is. `.py` must define `run()` taking no arguments — use it when
the data needs logic, like reading a CSV.

**Seeds must be safe to run twice.** Nothing tracks what has already run; every
`make seed` runs every file. So upserts, not plain inserts:

```sql
insert into api_fundingbody (code, name) values ('arc', 'Australian Research Council')
on conflict (code) do update set name = excluded.name;
```

A plain `insert` works the first time and breaks `make db-reset` forever after.

If a file is generated by a script, say so at the top — otherwise nobody can
tell whether editing it by hand is reasonable.

## Commands

```bash
make seed        # run everything
make seed-list   # show what would run, in order
```

`make setup` and `make db-reset` run seeds for you.
